# 移动端真实指纹库（Android / iOS）

> 状态：已实现并验证（2026-10）。适用内核：**fp-chromium**（`移动端 target_os 仅支持 fp-chromium`）。
> 本文是移动端指纹库的现状说明与扩展指南；早期设计过程见 `docs/移动端增强实现方案.md`。

## 1. 目标与总体架构

在桌面 Chromium（fp-chromium 内核）上模拟出**可自洽、可对抗常规移动端检测**的
Android / iOS 真机环境：UA / UA-CH / 屏幕 / DPR / 视口 / GPU / 系统版本 / 机型 /
内存 / 电池 / Safari 属性差异等信号全部相互印证，且**存储的指纹 = 运行期实际值**。

```
app/data/mobile_devices.json          真实机型库（数据源，可追加）
        │
        ▼
app/mobile_fingerprints.py            指纹引擎：按权重抽取机型 → 配对系统/浏览器版本
        │   产出统一结构 fingerprint_json（mode / fingerprint / seeds / fonts / health）
        ▼
app/fingerprint_engine.py             双模式入口 + 一致性体检（check_health）+ 摘要
        │
        ▼
app/kernels/fp_chromium_kernel.py     内核启动参数（--fingerprint 种子、platform 版本、UA、窗口）
        │   返回 ws_endpoint
        ▼
app/mobile_cdp_injector.py            CDP 注入层：设备度量 + UA 覆盖 + JS 原型补丁 + Sec-CH 头
        │
        ▼
真实浏览器（页面内所有移动端信号生效，新标签页自动套用）
```

## 2. 机型库（app/data/mobile_devices.json）

库版本 2026.10，共 43 款真实机型：Android 27 款（Samsung / Google / Xiaomi（含 Redmi）/
OnePlus / Honor），iOS 16 款（iPhone + iPad，Apple）。每款机型一条记录：

```jsonc
{
  "brand": "Samsung",              // 品牌（面板品牌筛选）
  "platform": "android",           // android | ios
  "type": "phone",                 // phone | tablet
  "model": "SM-S938B",             // 机型标识（Android UA / UA-CH model 使用）
  "market_name": "Galaxy S24 Ultra",
  "released": "2024-01",
  "weight": 40,                    // 在网权重（抽取概率）
  "screen": {
    "w": 1440, "h": 3120,          // 物理分辨率
    "dpr": 3.75,
    "css_w": 384, "css_h": 832,    // 浏览器可见 CSS 逻辑像素（w/dpr）
    "viewport_h": 756              // 首屏视口高：真机浏览器 UI 占位后的 innerHeight
  },
  "gpu": { "vendor": "Qualcomm", "renderer": "ANGLE (Qualcomm, Adreno (TM) 830, OpenGL ES 3.2)" },
  "cpu_cores": 8,
  "ram_gb": 12,
  "max_touch_points": 5,
  "os_versions": { "16": 45, "15": 40, "14": 15 }   // iOS 用 "ios_versions"
}
```

配套版本池：

- `android_browsers`：Chrome 主版本 → 完整构建号 + 在网权重（153~156，2026-10 快照）。
  **仅作没有安装内核时的回退**：正常情况下 Android 的 Chrome 版本自动跟随
  fp-chromium 内核的真实引擎版本（启动时探测 `Chromium --version`，如
  `148.0.7778.215`）——UA / UA-CH 声称的版本必须与引擎 feature 一致，
  声称 156 而引擎是 148 会被检测站直接标记「浏览器版本不同」。
- `grease_brand`：UA-CH 的 grease 品牌（`Not_A Brand;v="8"`）

> 提示：升级 fp-chromium 内核（更换 Chromium 大版本）后，引擎版本随之变化，
> 旧环境建议「编辑 → 重新生成指纹」以保持 UA 与引擎一致。

数据来源：屏幕/DPR/CSS 取自 Chrome DevTools 设备库实测值（与 Playwright deviceDescriptors
一致）与厂商公开规格；GPU 字符串为对应 SoC 在 Chrome(ANGLE)/Safari 下的真实上报格式；
系统版本分布为在网份额近似值。

### 新增机型

在 `devices` 数组按同结构追加一条记录即可（无需改代码），随后执行：

```bash
.venv/bin/python scripts/mobile_test.py          # 数据结构与一致性测试
```

## 3. 两种生成模式

| 模式 | 机型 | 系统版本 | 浏览器版本 | 字体 |
|------|------|----------|------------|------|
| `preset` 真实机型预设 | 按在网权重抽取 | 该机型权重最高的主流版本 | 内核真实 Chromium 版本（148.0.7778.215）/ Safari 随系统 / CriOS 跟随内核主版本 | 该平台完整集合 |
| `generate` 合成生成 | 按在网权重抽取 | 按权重随机 | 内核真实 Chromium 版本 / Safari 随系统 / CriOS 跟随内核主版本 | 随机子集 |

两种模式的底层数据都来自真实机型库（区别于「随机拼凑」的合成），preset 的差别是
**版本组合固定为当前主流**，适合需要稳定环境的场景；generate 产生分布内多样性。

- 品牌筛选：创建时可指定 `manufacturer`（Samsung/Google/Xiaomi/OnePlus/Honor/Apple），
  留空按在网权重随机；品牌不存在时引擎回退全库（API 层会直接拒绝非法品牌）。
- 浏览器口径：仅 iOS 可选 `browser`（`safari` 默认 / `chrome_ios`）。Android 恒为
  Chrome（传 `chrome_ios` 会被 API/引擎拒绝）；iOS 的 `chrome_ios` 产出 CriOS UA 并在
  运行期补齐 Chrome iOS 检测面（见 §4）。切换口径会强制重新生成指纹，后续改名/
  矩阵重生成/导入重生成都会保留原口径。
- 移动端指纹统一存放于 `fingerprint_json.fingerprint` 字段，`mode` 仅是模式标签
  （`preset` 字段仅桌面 camoufox 预设使用）。浏览器口径存放在
  `mobileExtra.browser`（`chrome` / `safari` / `chrome_ios`）。

## 4. 运行期真实化清单

内核（fp-chromium 148）对移动端支持有限，下列信号在 **CDP 注入层**落地
（`app/mobile_cdp_injector.py`，随 CDP 会话保持；新标签页自动套用）：

| 信号 | 真机表现 | 实现手段 |
|------|----------|----------|
| 屏幕 / DPR / 触控 | screen.width 为 CSS 像素，多点触控 | `Emulation.setDeviceMetricsOverride` + `setTouchEmulationEnabled` |
| 首屏视口 | innerHeight < screen.height（浏览器 UI 占位） | 由库中 `viewport_h` 注入；`innerH == screen.height` 是最典型穿帮点 |
| UA（JS + 请求头） | `Mozilla/5.0 (Linux; Android 16; SM-S938B) ... Chrome/148.0.0.0 Mobile Safari`（版本跟随内核引擎） | `Emulation.setUserAgentOverride` + 内核 `--user-agent` + **文档起点 JS 兜底**（CDP 覆盖是渲染器侧命令，新标签页首文档偶发在其落达前已提交——竞态实测；JS 补丁在文档起点同步覆盖 `navigator.userAgent`/`appVersion`，与 CDP 值一致） |
| navigator.platform | Android `Linux armv81`；iOS `iPhone`/`iPad` | JS 原型补丁（内核 CDP `platform` 参数无效） |
| **WebGL GPU 字符串** | `ANGLE (Qualcomm, Adreno (TM) 830, OpenGL ES 3.2)` / iOS `Apple GPU` | JS 包装 `getParameter(37445/37446)`（内核原生 GPU 伪装不支持移动平台，不补丁会暴露宿主 GPU）；包装层对这两个枚举值仍执行一遍原生调用再返回伪造值，调用吞吐保持原生量级（BrowserScan 计时器：5ms 内压测调用数，`Z = 次数/毫秒 > 100` 即判「WebGL exception」，纯 JS 缓存返回可达每毫秒数万次） |
| **WebGPU 适配器信息（`GPUAdapterInfo`）** | Android：口径与内核 Dawn 的 `gpu_info` 映射一致（148 内核二进制内嵌字面量实证，**代际级**）：Qualcomm `vendor: "qualcomm"`、`architecture: "adreno-Nxx"`（如 `adreno-7xx`/`adreno-8xx`）；ARM `"arm"` / `"valhall"`·`"gen-5"`；Samsung `"samsung"` / `"rdna-N"`；ImgTec `"img-tec"` / `"d-series"`；iOS 保持 Apple GPU（真机 iPhone 同为 Apple GPU）；`device`/`description` 为空串（真机同为空） | JS 原型补丁（`GPUAdapterInfo.prototype` 的 `vendor`/`architecture` getter；属性在原型上、实例无 own property、原型链不变）。宿主是 Apple GPU（`vendor: "apple"` / `"metal-*"`，与 WebGL 已声明的 Android GPU 直接矛盾，跨 API 一致性检查可命中）；页面与 Worker 补丁均覆盖（Dedicated Worker 同样可用 `navigator.gpu`） |
| **媒体设备枚举（`enumerateDevices`）** | Android：`videoinput ×2`（真机前后摄）+ `audioinput ×1` + `audiooutput ×1`；未授权时 label/deviceId/groupId 全为空串（Chromium 语义，与宿主一致） | JS 原型补丁（包装 `MediaDevices.prototype.enumerateDevices`，按类别分组并补足 videoinput 数量；合成条目走 `MediaDeviceInfo` 原型链——`instanceof` 成立、自身无 own property，字段 getter 在中间原型上）。宿主 Mac 单摄像头 → 原为 `videoinput ×1`，数量偏差可被设备枚举型检测直接捕获 |
| **UA-CH（Android）** | `navigator.userAgentData` 完整可用（brands / mobile / platform / 高熵 model、platformVersion、fullVersionList…）；`architecture`/`bitness` 恒为空字符串（Chromium 源码 Android 手机端行为） | JS 原型补丁（该内核完全不提供 UA-CH，CDP userAgentMetadata 参数无效）；旧指纹中误填的 `"arm"` 在运行期归一化为 `""` |
| **Sec-CH-UA\* 请求头（Android）** | 默认对全站发送低熵三头 | `Network.setExtraHTTPHeaders`（值由 UA-CH 生成） |
| **Accept-CH 高熵提示回送（Android）** | 站点响应 `Accept-CH: Sec-CH-UA-Model, …` 后，同源后续请求附上对应高熵头（model / platformVersion / fullVersionList / arch / bitness / wow64，与 JS UA-CH 同值） | Fetch 域：Document 响应解析声明（按源登记）→ 对该源后续请求 `continueRequest` 精确补头（低熵三头与 UA 保持）；内核完全不处理 Accept-CH。第三方上下文不回送——高熵头受 Permissions-Policy（默认 self）约束，真机亦然；iOS Safari 无 UA-CH，声明前后均不回送 |
| **speechSynthesis 语音列表** | Android Chrome 无语音枚举，`getVoices()` 恒为空数组 | JS 原型补丁返回空列表（宿主 macOS 暴露 180 个语音——婷婷/Albert/Samantha…——该数量是 BrowserScan 服务端 `isOSCorrect` 的直接输入，"Different operating systems" 即由 180 vs 安卓期望 0 触发） |
| **WebGL readPixels** | 像素纯净（无任何噪声） | 移动端启动内核时强制 `--disable-spoofing=canvas`：内核 canvas 伪装会给 readPixels 注入种子化噪声（纯红三角形 R≠A，如 `[254,1,0,255]`），被 BrowserScan 的「红三角 R 应恒等于 A」零知识检查捕获判 "WebGL exception" |
| deviceMemory（Android） | 上报桶值（物理 6GB→4，≥8GB→8） | JS 原型补丁；iOS 抹除 |
| Battery API（Android） | `navigator.getBattery()` 可用 | JS 补丁（含 EventTarget 兼容对象）；iOS 抹除 |
| colorDepth / pixelDepth | 移动端 24 | JS 补丁（宿主 macOS 报告 30，属明显穿帮） |
| **时区** | 与代理出口 IP 属地一致 | geoip 开启时探测出口时区 → 内核 `--timezone` + `Emulation.setTimezoneOverride`（显式 timezone 优先） |
| **补丁函数原生性** | 检测站在 JS 函数 `toString()` 里看不到包装痕迹 | `Function.prototype.toString` 接管：补丁函数返回 `[native code]` 外观（BrowserScan「Canvas Tampering」即由函数被包装触发） |
| iOS Safari 属性差异 | 无 `connection`/`pdfViewerEnabled`/`userAgentData`/`getBattery`/`deviceMemory`；`plugins`/`mimeTypes` 为空；`navigator.standalone === false` 存在 | JS 属性删除 + 空集合对象 + standalone 补丁 |
| **WebKit 缺失的桌面 Chromium API（iOS）** | Safari/WKWebView 从未实现：`navigator.serial` / `usb` / `hid` / `bluetooth` / `keyboard`（Keyboard Lock）/ `requestMIDIAccess` / `presentation` / `getInstalledRelatedApps` / `vibrate`；`window.showOpenFilePicker`（File System Access）；`performance.memory`（MemoryInfo）。桌面内核全部携带——`'serial' in navigator` 一行即可判「Chromium 装 iOS」 | 属性删除清单统一由指纹库 `_IOS_REMOVE_NAV_PROPS` 产出（运行期与数据层同源，避免两处漂移）；Window / Performance 原型级删除 + getter 兜底；Worker 内同样抹除 `performance.memory` |
| **WebKit 专有手势事件家族（iOS）** | `GestureEvent` 构造器 + `ongesturestart/ongesturechange/ongestureend` 处理属性；Chromium 全平台都没有（MDN BCD：chrome/chrome_android=false、safari_ios=2），是「Chromium 内核装 iOS」最直接的反证之一 | 补最小完备面：构造器为 `UIEvent` 子类（原型链/`instanceof` 成立）、`rotation`/`scale` 为原型访问器、处理属性挂在 `Window.prototype`（enumerable，与原生事件处理属性一致），函数均走 `[native code]` 外观 |
| **Android 的 PDF 面** | 真机 Chrome Android 无内置 PDF 插件（Chromium 构建开关 `enable_pdf=!is_android`）：`plugins`/`mimeTypes` 为空、`pdfViewerEnabled === false`（属性存在但恒 false，与 iOS 的「属性不存在」形态不同）。宿主桌面内核是 5 个 PDF 插件 + `true` | 指纹层置 `emptyPlugins=true`；运行期按平台收敛（存量 Android 指纹的 `emptyPlugins=false` 不再生效，无需重建）；`pdfViewerEnabled` 用 getter 固定为 `false` |
| **Android 的 WebHID 边界** | Chrome Android 不支持 WebHID（BCD `chrome_android=false`）；但 WebUSB / Web Serial / Web Bluetooth / Web MIDI 在 Chrome Android 148 均已支持，**不可按「桌面 API」一概抹除** | `_ANDROID_REMOVE_NAV_PROPS = ["hid"]` 单项抹除；其余保留。验证脚本对两侧都做了正反断言 |
| **iOS Chrome（CriOS）检测面** | UA 为 `CriOS/<major>.0.0.0`；页面世界存在 `window.__gCrWeb`（`windowId` + 约 30 个成员）、`window.webkit` 命名空间（WebKitNamespace 实例：`messageHandlers` 为只具名 getter 命名空间，含 `crwebinvoke` 与 `POSTSuccessHandler`/`POSTErrorHandler` 通道、通道名可读不可枚举；`buffers` 为空 WebKitBufferNamespace 实例；`evaluateScript`/`createJSHandle` 因 world 门控在页面世界缺席）、被改写的 `history.pushState/replaceState/back/forward/go`、`window.print`、`window.scrollTo`（`toString()` 可见 `invokeOnHost` / `setWebViewScrollViewIsDragging` 源码文本）；`standalone` 不存在；普通页面无 `window.chrome` | JS 原型/全局补丁（`__gCrWeb` 为普通可写属性，`windowId` 每窗口随机；被改写函数保留原生行为透传，仅替换 `toString` 源码文本，不伪装成 `[native code]`）。`window.webkit` 按 WebKit 机制装配：WebKitNamespace 实例，描述符同 JSC 惰性属性（`writable:false / enumerable:true / configurable:false`）；`messageHandlers` 只具名 getter 语义——`Object.keys` / `getOwnPropertyNames` 为 `[]`、`'crwebinvoke' in handlers` 为 true、`handlers.crwebinvoke` 可取值、未知名 `undefined`、`Object.getOwnPropertyDescriptor` 仍返回 `Writable|Enumerable|Configurable`；`crwebinvoke.postMessage` 原生外观且返回 pending Promise（页面世界分支无回执）；`buffers` 为 `LegacyNoInterfaceObject` 的 WebKitBufferNamespace 实例（全局无构造器、`[object WebKitBufferNamespace]`）。Worker 内不补——真机 CriOS 的 Worker 同样没有这些对象。通道全集与 POST 两通道的条件注入时机待真机抓取二次校准 |
| **`window.chrome` 边界（iOS 两口径通用）** | 真机 iOS Safari 与 Chrome 普通页面均无 `window.chrome` | 赋 `undefined` 后 `typeof`/truthiness 检查通过；`'chrome' in window` 与 `getOwnPropertyDescriptor` 的残余暴露属内核层限制（属性 `configurable:false`，无法删除）——已知边界 |
| **跨域 iframe（OOPIF）** | reCAPTCHA 等三方 iframe 内与主文档同一套信号（platform/屏幕/触控/GPU/UA-CH） | 页面级 `Target.setAutoAttach(waitForDebuggerOnStart)` 捕获 OOPIF（暂停于上下文创建前）→ 挂 init 脚本后放行；并以 `Target.setDiscoverTargets` + 显式 `attachToTarget` 兜底（auto-attach 投递存在多客户端竞争）。补丁镜像 screen/DPR/outer/orientation——OOPIF 是独立进程，不继承 CDP 度量仿真，否则泄漏宿主 1440×900/DPR2/横向 |
| **Worker（页面 + iframe 内）** | WorkerNavigator 的 platform/UA-CH/deviceMemory/UA 与主文档一致（安全上下文下内核原生给桌面 Linux 元数据） | Worker 目标被门控暂停时 `Runtime.evaluate` 注入 Worker 补丁（实测暂停态 1–2ms 响应，先于脚本首行），随后放行 |
| **输入事件层（点击 / 滚动）** | 真机上不存在桌面鼠标输入：点击是触摸序列（`touchstart` → `touchend`，随后兼容鼠标事件与 `pointerType=touch` 的 `click`），滚动是触摸拖拽（`touchmove` 序列）。`pointerdown:mouse` / `mousedown` 首事件 / `wheel` 都是「手机壳桌面输入」的直接证据（行为型风控的重点面） | 移动端环境的面板点击、RPA `click`/`scroll` 自动改走 CDP `Input.dispatchTouchEvent`（`app/mobile_input.py`）：`tap_locator` 取元素中心点派发 `touchStart`→`touchEnd`，`touch_scroll` 派发 `touchStart`→多段 `touchMove`→`touchEnd`。**不启用** `Emulation.setEmitTouchEventsForMouse`——实测 fp-chromium 148 会吞掉 `mousePressed/Released` 的 CDP 应答导致 Playwright 点击永久挂起，且转换产物缺兼容鼠标事件与 `click` |
| **传感器事件流（Android）** | 真机 Chrome Android 持续派发 `devicemotion`（60Hz 级、`interval=16`、数值非 null）与 `deviceorientation`（`absolute=false`）/`deviceorientationabsolute`（`absolute=true`）；桌面内核无传感器，只在注册监听时派发一次全 null 哨兵事件——「有没有连续数值流」是最直接的模拟器/桌面判据。跨域 iframe 受 Permissions Policy 门控（`devicemotion` 需 `accelerometer`/`gyroscope` 特性，默认 allowlist=self）：未声明 `allow` 的子帧真机同样零事件 | CDP 虚拟传感器（`Emulation.setSensorOverrideEnabled/Readings`，5 类映射：`accelerometer`→`aig`、`linear-acceleration`→`acc`、`gyroscope`→`rr`、`relative/absolute-orientation`→两个 orientation 事件）；**必须在页面注册监听前启用**（实测：请求在「无传感器」态定型后不再派发）→ 挂载于目标 attach 的 `waitForDebuggerOnStart` 暂停期；虚拟传感器是**浏览器进程级全局对象**（其他目标 enable 报 `already overridden`）→ 单条读数循环，与真机「所有页面共享同一份传感器数据」一致；读数模型：姿态（β∈[55°,75°]、γ∈[−10°,10°]、α 自由）与重力严格同源（`aig = (−g·cosβ·sinγ, g·sinβ, g·cosβ·cosγ)`）+ 随机游走 + 0.05s±40% 抖动（读数为 1dp 量化，与真机一致） |
| **iOS 传感器权限面** | Safari 有 WebKit 专有 `DeviceMotionEvent/DeviceOrientationEvent.requestPermission`（iOS 14.5+；无手势 → reject `NotAllowedError`，手势内 → 弹系统授权框、Promise pending）；`DeviceOrientationEvent.prototype.absolute` 不存在（BCD `safari_ios=false`）；无 `deviceorientationabsolute` 事件（WebKit 全平台）；未授权时完全不派发传感器事件 | 模板层补 `requestPermission`（无手势 reject `NotAllowedError` 原文案；手势内保持 pending——不伪造 granted/denied）、抹除 `absolute` 与 `ondeviceorientationabsolute`；不派发数值事件（与真机未授权口径一致）；文档起点注册捕获阶段监听，以 `stopImmediatePropagation` 抹掉内核派发的一次全 null 哨兵事件（仅拦 `isTrusted`，脚本自派发不受影响）→ 未授权时事件总数 0 |
| **iOS 引擎面（全屏 / CSS 前缀 / 传感器构造器 / Safari 全局面）** | iPhone 无元素级全屏（BCD 16.4 注「Only available on iPad, not on iPhone」；WebKit Fullscreen IDL 由 `FullScreenEnabled` setting + `shouldDisableElementFullscreen` quirk 门控），`<video>` 有 webkit 全屏家族（iPhone 唯一元素级全屏通道）；`CSS.supports('-webkit-touch-callout', …)` 与 `'webkitTouchCallout' in el.style` 为 true（WebKit 专属；值域 `default\|none` / `auto\|touch`）；传感器构造器不可构造（`new` 抛 TypeError）；iOS 才有 `webkitCompassHeading/Accuracy`、legacy `initDeviceMotionEvent` / `initDeviceOrientationEvent` 与 `document.createEvent('DeviceMotionEvent'/'DeviceOrientationEvent')`；**Safari 全局面**（Safari 与 CriOS 同为 WebKit 运行时，均具备）：`WebKitPoint`、`webkitConvertPointFromNodeToPage`/`…PageToNode`、`webkitCancelRequestAnimationFrame`、`WebKitNamespace`/`UserMessageHandlersNamespace`/`UserMessageHandler` 接口对象；`window.webkit` 实例只在宿主为页面世界注册过消息处理器时出现（Safari 无、CriOS 有 `crwebinvoke`） | 模板层：iPhone 删 22 个全屏成员（iPad 保留）、补 6 个 `<video>` webkit 全屏成员（supports/displaying 状态机）、CSS 前缀白名单 + `CSSStyleDeclaration` 访问器 + CSSOM 方法桥接、Proxy 不可构造替换、罗盘访问器 + legacy 初始化器 + `createEvent` 全链、`WebKitPoint` + 两换算方法（border box + 页面滚动偏移）+ `webkitCancelRequestAnimationFrame` 别名 + namespace 三接口对象（不可构造；页面世界原型成员集），CriOS 另装配 `window.webkit`（verify 逐项断言） |
| 非标准属性 | —— | 不伪造 `navigator.mobile`（真实 Chrome/Safari 均无此属性，伪造反而成为指纹） |

JS 补丁全部定义在原型上（`Navigator.prototype` / `Screen.prototype` /
`WebGLRenderingContext.prototype` / `NavigatorUAData.prototype` / `BatteryManager.prototype`），
`Object.getOwnPropertyNames(navigator)` 与 `userAgentData` 均无 own-property 泄漏；
属性描述符对齐原生（`enumerable`/`configurable` 同真机）。

### 新标签页竞态门控（waitForDebuggerOnStart）

仿真应用是异步的。若新标签页在仿真挂上之前就加载并执行页面脚本，会得到
「UA 是移动端、屏幕/GPU/触控全是宿主值」的混合指纹——这是移动端仿真最隐蔽的
穿帮。注入层对自动挂载的新目标使用 `Target.setAutoAttach(waitForDebuggerOnStart:
true)`：目标在调试器处暂停，`Page.addScriptToEvaluateOnNewDocument`（紧跟
`Page.enable` 挂载，路径最短化）与设备度量、UA、请求头全部就绪后才
`Runtime.runIfWaitingForDebugger` 放行——首个文档必然在补丁生效后执行。

> 门控细节（实测）：resume 是**会话级**的——只有收到 `waitingForDebugger: true`
> 投递的那个会话能解除暂停；同一目标出现重复投递（多客户端/多配置）时，去重
> 逻辑必须等先到者完成补丁注册后由各自的会话放行。自动化工具（Playwright 等）
> 抢走 OOPIF 的 auto-attach 投递时，`Target.setDiscoverTargets` 兜底路径仍会
> 显式挂载并补丁。

## 5. 一致性体检（check_health）

创建/更新环境时静态校验并落库，跨信号矛盾是最主要的反检测破绽。移动端专项规则：

- UA 与机型对照：Android UA 含档案机型与 `Android {版本}`；iOS UA 含 `OS {版本}`
- UA-CH：Android 必须存在且 `model` == UA 机型、`architecture`/`bitness` 为空串；iOS 不得存在
- Battery：Android 必须有数据；iOS 不得有
- 物理分辨率 / DPR / CSS 宽度相互印证（误差 ≤1px）
- 首屏视口高 ∈ (0.5×CSS 高, 0.95×CSS 高)，视口纵横比合理
- GPU 字符串格式：Android `ANGLE (` 前缀；iOS 渲染器 `Apple GPU`、厂商 `Apple Inc.`
- 通用项：devicePixelRatio 1.5~4.5、CSS 宽 300~1400、hardwareConcurrency 1~64、种子/字体齐全

## 7. API 与面板

- `GET /api/v1/mobile-devices`：机型库信息（版本/品牌/机型清单，面板品牌选择器数据源）
- `POST /api/v1/profiles`：新增可选字段 `manufacturer`（仅 android/ios 生效）、
  `browser`（仅 iOS：`safari` / `chrome_ios`；Android 仅接受 `chrome`）
- `PUT /api/v1/profiles/{id}`：改品牌/系统/模式/浏览器口径会重新生成指纹；
  只改名/改其他字段时保留原口径
- MCP `create_profile`：同样支持 `manufacturer` / `browser` 参数
- 面板：目标 OS 选 Android/iOS 时自动切内核、显示「机型品牌」选择器；选 iOS 时
  额外显示「浏览器口径」选择器（Safari / Chrome CriOS），编辑档案时回填原口径；
  指纹模式 preset/generate 均可用（摘要标签区分「真实机型预设 / 合成生成 (移动端)」）

## 8. 已知边界与后续可增强项

- **iPad UA 为简化口径**：真机 iPadOS 13+ 默认桌面模式上报 Mac UA，本库统一用
  `(iPad; CPU OS ...)` 移动 UA（行为更像"请求桌面网站"关闭态），后续可切换。
- `navigator.languages` 固定 zh-CN 家族（与 locale 联动可精细化）。
- WebGL 仅补 UNMASKED 厂商/渲染器；扩展能力集（如 `EXT_disjoint_timer_query`）仍为内核默认。
- **WebGPU Android 口径为代际级**（与内核 Dawn 数据一致）：映射规则取自 148 内核
  二进制内嵌的 Dawn `gpu_info` 字面量（`adreno-4xx`..`8xx` / `valhall` / `gen-5` /
  `rdna-1`..`4` / `d-series`），按机型 WebGL 渲染器还原；库外 GPU 不伪造（不下发
  WebGPU 补丁）。iOS 保持宿主 Apple 适配器（真机 iPhone 同为 Apple GPU，无需伪装）。
  iOS 上架构字符串与 WebKit 实现的细微差异属「内核是 Chromium」的架构边界。
- **媒体设备仅对齐枚举层**：未授权枚举（`enumerateDevices` 数量/掩码，风控主要信号）已
  对齐真机；若真实授权 `getUserMedia` 采集，走的仍是宿主设备（未做虚拟摄像头/麦克风）。
- 内核 canvas 伪装在移动端被关闭（防 readPixels 噪声被零知识检查捕获），
  代价是 canvas2d 哈希退化为宿主真实渲染、环境间不隔离；如需恢复隔离，
  应在注入层实现「读取路径一致、不触碰 readPixels」的种子化 canvas 噪声。
- Battery/deviceMemory 为静态值（真机会随时间变化）；对多数风控足够，长会话场景可加动态。
- **X-Client-Data 不注入（已实测决策）**：该头是真机 Chrome 仅对 Google 域发送的
  实验分组数据；实测本内核对所有域（含 google.com）都不发送。伪造值可能与 Google
  服务端预期不符（反而引入异常），且非 Google 域本就不应出现该头——维持不发送。
- 字体子集随环境存储（结构兼容桌面）；fp-chromium 下字体指纹渲染由内核种子驱动。
- iOS 的引擎仍是 Chromium：Safari 版本号与引擎 feature 无法一致（无 WebKit 引擎），
  为架构性限制；主流动检测站的实际扣分点（GPU/屏幕/触控/属性差异）已覆盖。
- **iOS Chrome 的 `__gCrWeb` 为静态补丁**：成员名与 `toString` 源码文本来自 Chrome 61
  真机抓取分析（`docs/Chrome61-IPA检测机制分析.md`），但现代 CriOS 的成员全集/通道名
  尚未二次抓取；`windowId` 格式为随机 hex（真机为宿主填充，格式待校准）。检测站若
  比对成员数量或特定方法名，仍可能命中差异。`PaymentRequest` polyfill（B1-8）默认
  接受原生实现形态差异，不断言。
- **CriOS 的 `window.chrome` 残余暴露**：与 Safari 口径相同，`'chrome' in window` 与
  `getOwnPropertyDescriptor` 仍能看到内核属性（`configurable:false` 无法删除），
  属内核层限制。
