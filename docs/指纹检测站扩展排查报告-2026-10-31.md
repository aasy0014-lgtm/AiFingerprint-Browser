# 指纹检测站扩展排查报告（2026-10-31）

## 范围

在一次性 Android/Xiaomi 15 Ultra 环境中逐站打开 37 个公开检测入口，并对
BrowserScan、JustBrowser、ProxyLabs、CreepJS 等动态页面等待到结果完成。采样脚本只
读取公开页面信息，不输入账号、不提交表单；原始 JSON 可用：

```bash
.venv/bin/python scripts/detect_sites_probe.py --wait 2 --output /tmp/fpwb-detect.json
```

## 主要发现

### P0：出口属地与移动环境不一致

- 出口 `47.254.29.8` 被 BrowserScan/JustBrowser/Device Info 识别为美国洛杉矶/加州，
  IP 时区为 `America/Los_Angeles`。
- 环境 JS/Intl 为 `Asia/Shanghai`、`zh-CN`；BrowserScan 给出 `Bot Detection: NoDetection`
  但总分约 80%，扣分项为 `Different time zones -10%` 与 `Language mismatch -10%`。
- JustBrowser 为 `5 Pass / 3 Warn / 0 Fail`，地理位置行同样提示 UTC-0700 与浏览器时区
  不匹配。

这是最需要先处理的跨信号矛盾。登录环境应让出口地区、时区、语言保持同一组合；不要
用随机噪声或频繁切换指纹解决它。

### P0/P1：Canvas 仍暴露宿主渲染特征

- BrowserLeaks Canvas 页仍提示 `Chrome + Mac`、`Mac 10.15`、`MacIntel`，唯一性约
  99.99%。这与 Android UA、Qualcomm WebGL renderer 不一致。
- 同一会话的固定探针在主文档可稳定读取，但站点仍能从 Canvas 的字体/像素渲染判断
  宿主平台；后续应优先收敛 Canvas 与 Android 字体/渲染口径，并继续做 iframe/worker
  对拍。

### P1：CreepJS 仍有自动化/内核侧信号

- `chromium: true`、`38% like headless`，但 `0% headless`、`0% stealth`。
- 字体探针报告 4/51 命中，包含 `"Dancing Script"`, `"Droid Sans Mono"`,
  `"Noto Color Emoji"`, `Roboto` 等宿主/字体回退痕迹。

这说明 `navigator.webdriver=false` 不是完整结论，窗口/字体/Worker/内核行为仍要一起
对齐。

### P1：ProxyLabs 报告的可见问题

等待 21 个模块完成后得到：

- Uniqueness `27/100`、Spoofing Risk `40/100`、Leak Risk `75/100`。
- Spoofing Detection 的两个条目：`userAgent toString is spoofed`、`0 plugins is
  suspicious for non-headless`；Headless/Bot 模块有一个 `0 plugins in Chrome` 信号。
- Intl 模块提示 `Locale inconsistency detected: zh-CN, en`。
- HTTP Headers 模块显示 Proxy detected；该页面同时看到 Cloudflare/CDN 的
  `x-forwarded-*`、`cdn-loop` 等反向代理头，不能直接归因于本地代理。

其中 `userAgent toString is spoofed` 是该站自身的弱校验：它把字符串值的
`navigator.userAgent.toString()` 与原生函数的 `toString()` 混为一谈，普通 Chrome
也会满足该条件；`0 plugins` 与 `en-US, en` 则分别是 Android Chrome 的空插件列表
和正常语言优先级。三项保留为观测项，不作为本项目的登录阻断条件。

Canvas 模块还显示 `Canvas noise detected`。我们在普通 Chromium 内核上复现了该站的
“同一几何图形清空后重绘、两次 `toDataURL` 必须相等”测试，基线也返回不相等，因此
该条更像站点测试与 Chromium 合成状态的兼容性误报；它仍值得保留为回归项，但不应
单独据此增加随机噪声。

### P2：移动端规格导致的站点误报

- Sannysoft 把 `plugins.length=0` / `PluginArray` 标红；这是桌面 Chrome 规则，Android
  移动 Chrome 为空是预期，不应为了通过它伪造桌面 PDF 插件。
- JustBrowser 的 `chrome.runtime Missing`、`Plugins None` 同样是移动/精简内核提示，
  需与真实 Android 基线比较，而不是单独当成登录失败。
- CreepJS Checker 被 Cloudflare 挑战，PrivacyTests/CleanIP 需要手动点击开始扫描；
  这些结果在自动采样中只记为“未完成”，不作为风控失败。

### 新增站点后的收敛顺序

1. 先让出口 IP 的地域/ASN 与 profile 的时区、语言形成同一组合；当前是
   BrowserFingerprint.org、XDLogin、JustBrowser 三站重复出现的矛盾。
2. 托管云出口会被 XDLogin 标为 `hosting/datacenter network`；如业务必须模拟家庭/移动
   网络，应更换与目标地域一致的出口，而不是改 Canvas 或随机化指纹。
3. Canvas/WebGL/Audio/字体的高暴露属于稳定环境面；先保证 Android 设备规格彼此一致，
   不要用每次加载都变化的噪声破坏连续性。
4. 需要点击的站点在报告中明确标记“手动扫描”，并与自动完成的检测结果分开。

## 修复后复测

已修复 GeoIP 只在配置代理时才生效、且只采用首个 GeoIP 服务结果的问题：

- 现在直连和代理都读取多个来源，以时区/国家多数票为准；本出口 3 个来源中 2 个
  返回 `America/Los_Angeles`，不再采用 ip-api 单独返回的错误 `America/New_York`。
- fp-chromium 移动环境启动时会把出口时区与属地语言一起传入 CDP；管理端重启后，
  同一 Xiaomi 环境运行期变为 `America/Los_Angeles` + `en-US`。
- JustBrowser：`6 Pass / 2 Warn / 0 Fail`，时区警告消失；剩余 `chrome.runtime`
  缺失属于移动 Chrome 的弱提示。
- XDLogin：由 `2 flags / 3 OK` 收敛为 `1 flag / 4 OK`，时区与语言均通过；剩余项是
  Alibaba Cloud 托管网络。
- BrowserScan 综合页显示 IP 时区 `America/Los_Angeles` 与浏览器一致，检测语言为
  `English (United States)`。
- 复用现有 `xiaomi` 环境（配置的美国代理）复测：JustBrowser 读取
  `America/New_York`，XDLogin 为 `0 flags / 5 OK`；WebRTC 未暴露公网 IP，说明代理
  场景的时区/语言收敛已经生效。
- Android 与 iOS 的本地登录链路回归均通过：触摸点击产生 OAuth 弹窗，Cookie、
  localStorage、IndexedDB 持久化，sessionStorage 在重启后清空；两端语言均为
  `en-US / [en-US, en]`。
- Canvas 对照实验已收敛：恢复移动 Canvas 伪装后，BrowserLeaks 不再把 Android
  环境识别为 `Chrome + Mac`，BrowserScan 的 OS/GPU/时区口径仍为 Android/Qualcomm，
  WebGL readPixels 未出现异常；BrowserLeaks 的 `100% unique` 属于可见度提示，优先级
  低于 Android 与宿主平台矛盾。

因此，最主要的跨域矛盾已解决；当前主要剩余项是云数据中心出口质量，以及 Canvas/
WebGL/字体的高可见度，不再是浏览器时区漂移。

## 结论与下一步

1. 继续处理 Canvas 的 Android 渲染/字体一致性；不要用每次随机变化的 Canvas 噪声。
2. 对 CreepJS 的 `38% like headless`、ProxyLabs 的 `userAgent toString` 做单独回归，
   保留移动端合理的空插件列表。
3. 如需继续降低网络侧风险，更换与目标地域一致的住宅/移动出口；云数据中心标签
   不是 Canvas 参数可以抵消的。
4. 复测 BrowserLeaks Client Hints，确认 HTTP `DPR`、`Device-Memory` 与 JS 的
   `3.5`、`8` 一致；管理端已重启，检测入口为 37 个。

## 剩余项处理（本轮）

### CreepJS `like headless`

采样脚本现在同时读取 `window.Fingerprint.headless.likeHeadless` 的原始布尔项，
不再只根据百分比下结论。Android Chrome 的 `noPlugins`、`noMimeTypes`、
`pdfIsDisabled`、`noTaskbar` 以及浅色移动主题下的 `hasKnownBgColor`、
`prefersLightColor` 都被记录为 `expectedFlags`；同时保留 `fontProbe` 原始列表，
便于和机型字体子集对拍。只有 `actionableFlags`、
`headless` 或 `stealth` 项进入失败摘要。这样保留 CreepJS 原始 38% 结果，
同时避免把 Android 的平台事实误报为自动化阻断。

### ProxyLabs / BrowserScan 弱启发式

- ProxyLabs 的 Canvas noise、空插件、`userAgent toString`、`en-US, en` 等
  条目现在进入 `notes`/`knownWeakHeuristics`，未知 spoofing 信号才进入
  `issues`；Canvas 结果也改为有界匹配，避免整页帮助文案污染摘要。
- BrowserScan 同时兼容 `Bot Detection: 100%` 与带 `NoDetection` 标记的旧格式，
  并记录 `detectionLocale`、IP/Intl 时区和一致性结果。页面文案与实际采样值
  一致时只记 note，不再作为语言/时区失败。
- 数据中心/托管网络仍是出口质量项，报告会保留网络 note；更换住宅或移动出口
  才能改变该项，修改浏览器指纹不会改变 ASN。

### 扫描流程稳定性

- Sannysoft 的 `plugins-length-result` / `plugins-type-result` 按桌面 Chrome 规则
  检查插件；Android 空 `PluginArray` 会保留在原始结果中，但在摘要中归类为移动端
  预期。
- BrowserFingerprint、Panopticlick、VoriTools、SpeedIQ 等需要按钮或授权的页面现在
  记入 `notes`，不再伪装成环境失败；跨站采样遇到一次性导航错误会做三次有界重试。
