# 移动端大厂检测对抗优化方案

> **方法**：真实运行态实证（探针读数）→ 与真机口径逐项比对 → 按「检测收益 / 误伤风险」排序修复（P0 直接落地，其余给出设计与验证方法）。
> **口径来源**：MDN Browser Compat Data / caniuse（2026-10）、Chromium 源码构建开关（`enable_pdf=!is_android`）、liarjs.dev、本项目既有报告（[`Chrome61-IPA检测机制分析.md`](Chrome61-IPA检测机制分析.md)、[`Chrome61-IPA补丁方案.md`](Chrome61-IPA补丁方案.md)、[`移动端真实指纹库.md`](移动端真实指纹库.md)）。
> **覆盖的检测面**：极验 / 网易易盾 / 顶象 / 腾讯天御（行为 + 环境取证）、BrowserScan / FingerprintJS / CreepJS（属性面）、Cloudflare / Akamai / DataDome / HUMAN / Kasada / reCAPTCHA（行为 + 网络层）。
> **不变量**：不改动已存指纹数据；不改动既有条目的屏幕 / DPR 值；新机型必须为真实规格；移动端 target_os 仅支持 fp-chromium 内核。

## 1. 探针方法与复现

| 项 | 说明 |
| --- | --- |
| 脚本 | [`scripts/mobile_bigtech_probe.py`](../scripts/mobile_bigtech_probe.py)（诊断用，输出 JSON） |
| 路径 | 通过 `LaunchManager.start` 走完整启动链（fp-chromium 内核 + CDP 注入），页面带 `<meta name="viewport">`，读取的是**运行期真实读数**而非存储值 |
| 机型 | 固定对照：Android = Xiaomi 15（css 400×890、vp 814、DPR 3）；iOS = iPhone 17（css 402×874、vp 681） |
| 命令 | `.venv/bin/python scripts/mobile_bigtech_probe.py android` / `... ios`（可选第二参数指定机型） |
| 读数面 | 媒体查询 / 指针与触控 / 事件层（鼠标与 CDP 触摸派发）/ 屏幕几何 / Navigator 与平台 API / 插件与 PDF 面 / WebGL 参数与扩展 / Worker 与跨域 iframe / 请求头 |

**判读原则**：优先消除「一行代码即可判假」的单点信号（桌面独有 API 的存在性、桌面鼠标事件序列、桌面 PDF 插件面），再处理需要数值校准的面（传感器、GPU 上限、编解码）。

## 3. 缺口清单（按优先级）

### P0 —— 本轮已落地（见 §2 与 §4）

事件层触摸语义、Android PDF/插件面、Android WebHID、iOS 平台 API 抹除（12 项）、iOS 手势事件家族。

### P1 —— 建议下一轮实施（收益高、需真机校准）

| # | 缺口 | 检测面依据 | 修复设计 | 验证方法 |
| --- | --- | --- | --- | --- |
| P1-1 | Android `navigator.connection.type === null` | 真机 Chrome Android 返回 `wifi` / `cellular`（NetworkInformation `type` 仅 Android 实现）；桌面 Chrome 无 `type`。正反两面都可判读 | 注入层 `defineGet(N, 'type', 'wifi')`（属性已在原型上，保持可枚举/可配置形态）；如面向移动网络场景可配置为 `cellular` | 探针读 `connection.type`；`mobile_test.py` 增数据层标记 |
| P1-2 | 传感器事件流缺失（`DeviceOrientationEvent` / `DeviceMotionEvent` 无事件可触发） | 真机有周期性事件；部分风控验证「是否收到传感器事件」而非数值 | 事件类型与权限面 + 周期性 `dispatchEvent`（数值形态需真机采样）；次选 CDP `Emulation.setSensorOverrideReadings`（内核支持度待验证） | 真机对照采样（方向/加速度分布）；断言「监听后 N ms 内至少收到 1 次事件」 |
| P1-3 | iOS `window.webkit` 命名空间 | 非 WebView 的 iOS 浏览器亦有 `window.webkit`（含 `messageHandlers` 空对象等）；Chromium 无 | 补最小命名空间（需真机 `Object.getOwnPropertyNames(window.webkit)` 采样后按形态补） | 真机采样比对；先做 Safari/iPhone 真机取证再落地（避免补多补错） |
| P1-4 | 媒体可播放能力（`canPlayType`）跨平台差异 | iOS Safari 不支持 `webm/vp9`、`opus` 等；Android Chrome 支持——单行判「不是 iOS」 | 在 iOS 目标上按真机能力表校准 `HTMLMediaElement.prototype.canPlayType`（表放在指纹库，机型级） | 真机能力矩阵（Safari 机型矩阵 + Chrome Android 对照）；断言常见 MIME 返回值 |

### P2 —— 需要数据积累或更大改造

| # | 缺口 | 说明 | 修复设计 |
| --- | --- | --- | --- |
| P2-1 | WebGL `MAX_*` 上限与扩展集是**宿主 GPU**（Apple M 系列）值，与宣称的 Adreno/Mali/Apple GPU 不匹配 | 高级检测（gpuinfo.org 数据集/自建基线）可比对「渲染器字符串 × 参数上限 × 扩展集」三元组 | 采集 gpuinfo.org 对应机型样本，落到机型库（每 GPU 型号一组 `MAX_*` + 扩展集），注入层覆盖 `getParameter` 与 `getSupportedExtensions`（注意已有 `__maskNative` 伪装与噪声一致性） |
| P2-2 | iOS `Notification.permission` / `maxActions` | 真机 Safari `Notification` 行为与桌面 Chromium 不同（权限默认值/动作数上限） | 真机采样后按值注入（保持原型形态） |
| P2-3 | 输入层「内核级触摸化」 | 当前触摸语义只覆盖本项目 API / RPA 引擎；外部工具若直接发 CDP 鼠标命令仍会露出桌面序列 | 在 `ws_endpoint` 前挂 CDP 翻译代理（`Input.dispatchMouseEvent` → `Input.dispatchTouchEvent`，含拖拽/长按映射），保留原样应答；属于基础设施改造，收益是「所有下游自动化统一真机语义」 |
| P2-4 | 触摸拖拽不含系统惯性（fling）与压力曲线 | 行为型风控的高级模型会看速度剖面 | 在 `mobile_input.py` 加「速度曲线 + 松手惯性滚动」参数（等待步长/加速段），并在 verify 中断言事件数 ≥ N |
| P2-5 | `CSS.supports('-webkit-touch-callout')`、`env(safe-area-inset-*)` 计算值 | 前者是「有没有 WebKit 前缀支持」的弱信号；后者属于壳能力（无壳时全 0，真机非壳浏览器也非 0） | 评估后决定：前者 JS 可补（`CSS.supports` 白名单）；后者留缺口（补了更容易出错） |

### P3 —— 架构边界（明确不做或无法做）

| 项 | 说明 |
| --- | --- |
| `window.chrome` 深掩 | 内核层限制：`'chrome' in window` 与属性描述符残留（既有文档已记录）；只在 iOS Chrome 口径上置 `undefined` |
| JA3 / JA4 / HTTP/2 指纹 | 同版本 Chromium 跨平台基本一致，不构成移动/桌面判据；由代理层处理 |
| 字体枚举差异 | 宿主为 macOS，字体面接近桌面；与「Android/iOS 真机字体表」差异需在内核层或 JS 层按机型伪造（高成本、易伤渲染） |
| 传感器数值精确复刻 | 需要真机采样数据集与噪声模型，P1-2 先解决「有事件」，数值精度留后续 |

## 5. 附录：事件层内核缺陷实证（为什么禁用 emit-touch）

对 fp-chromium 148 做 2×2 对照（`scripts/mobile_bigtech_probe.py` 同源方法，直接读 CDP 应答与页面事件序列）：

| 配置 | CDP 鼠标命令应答 | 页面事件序列 | 结论 |
| --- | --- | --- | --- |
| `setEmitTouchEventsForMouse(mobile)` | `mouseMoved` 正常；**`mousePressed/Released` 无应答（永久挂起）** | `pointerdown:touch → touchstart → pointerup:touch → touchend`（**缺**兼容鼠标事件与 `click`） | 会导致 Playwright 点击挂起，且序列不完整：不可用 |
| 关闭该开关 | 全部正常 | 桌面鼠标序列（`pointerdown:mouse / mousedown / …`） | 仅适合桌面目标 |
| `setEmitTouchEventsForMouse(desktop)` | `mouseMoved` 正常；`press/release` 挂起 | 同 mobile 配置 | 不可用 |
| `Input.dispatchTouchEvent`（触摸派发） | 全部正常 | 完整真机序列（触摸 + 兼容鼠标事件 + `click:touch`） | **采用此路径**（`app/mobile_input.py`） |

> `page.touchscreen.tap` 在 `connect_over_cdp` 的默认上下文不可用（`hasTouch must be enabled on the browser context`），因此移动端自动化统一走 CDP 触摸派发；verify 脚本对「鼠标命令应答正常」保留守卫断言，防止将来有人打开 emit-touch 开关造成点击挂起。

## 6. 真机校准建议（下一步）

1. 在真机 Android Chrome（建议含一台 Wi-Fi、一台蜂窝网络设备）与 iOS Safari 上跑同一探针脚本，取 `probe_android.json` / `probe_ios.json` 基准；
2. 优先校准 P1 列表：`connection.type`、传感器事件（数值分布）、`window.webkit` 形态、`canPlayType` 矩阵；
3. 用 gpuinfo.org 采样补 P2-1 的 `MAX_*` / 扩展集表（按 GPU 型号，不按机型，避免组合爆炸）；
4. 校准后把「真机基准」纳入本仓库文档，任何注入改动都以该基准为准绳。
