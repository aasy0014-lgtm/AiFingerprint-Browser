================================================================================
注入网页的用户脚本清单（stable.app/*.js）
================================================================================
共 16 个 .js 文件，全部位于 Payload/stable.app/ 根目录（非加密资源，可直接读取）。
Chrome iOS 通过 WKUserScript 机制把其中多数注入到**页面世界(page world)**，
因此网站 JS 可以直接看到它们留下的全局变量与改写痕迹。

关键结论
--------------------------------------------------------------------------------
1) 普通网页里存在 window.__gCrWeb（约 30 个成员）→ 网站一句
   `'__gCrWeb' in window` 即可判定 Chrome iOS。
2) history.*、window.print、window.scrollTo 均被改写；被改写函数 toString()
   可见 "invokeOnHost" 字样 → 可用于二次确认。
3) 普通网页中 window.chrome 不存在（只有 WebUI 页面通过 web_ui_bundle.js 注入）。
   这是 Chrome iOS 与桌面 Chrome 的显著差异，可被风控当作指纹。
4) 表单类脚本 (autofill/password/suggestion) 会读取表单结构与字段；
   contextualsearch / language_detection 会读取选中文本和正文文本上报宿主进程。
5) cast_sender_iframe.js 只在页面使用 Cast 时注入，注入后 chrome.cast 全局可见。
6) post_request.js 只在发生 POST 导航时启用，暴露 __crPostRequestWorkaround
   与两个 webkit.messageHandlers 通道名。
